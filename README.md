# Тестовое задание для IT Solutions

Перед запуском нужно создать файл .env из файла .env.example и указать нужные значения в переменные окружения

## Запуск через Docker

`docker compose up -d`

## Запуск локально в dev моде

- Закомментировать сервис `app-back` в файле docker-compose.yaml
- Запустить БД в докере через docker-compose.yaml, выполнив команду `docker compose up -d`
- `npm install`
- `npm run contract:emit`
- `npm run db:init`
- Заполнить в файле `src/prisma/seed.ts` базовую информацию о себе, структура указана в файле
- `npm run db:seed`
- `npm run dev`

## Пример запроса

```graphql
query Profile {
    profile {
        id
        name
        title
        description
        links {
            type
            url
        }
        skills {
            name
        }
        experience {
            company
            position
            startDate
            endDate
            description
            achievements {
                text
            }
        }
        projects {
            name
            url
            description
            technologies
        }
    }
}
```

## Архитектурные решения

### 1. БД

Корневая сущность `Profile`, от неё идут связи "один ко многим" к ссылкам, навыкам, опыту и проектам, а от опыта к достижениям

### 2. Prisma 8

Проект создавался через `npm create prisma@latest`. Модель описана в `src/prisma/contract.prisma`. Команда `npm run contract:emit` генерирует из контракта файлы `contract.json` и `contract.d.ts`. Команда `npm run db:init` создаёт таблицы из контракта

### 3. GraphQL

Разработка велась по code-first, а не model-first. Схема описывается классами в файлах `src/profile/models/` и генерируется автоматически при префетч-запросе через `autoSchemaFile: true`. Так как схема небольшая, то можно обойтись без отдельного `.graphql` файла + это исключает рассинхрон между схемой и резолвером

GraphQL модели не совпадают с контрактом призмы намеренно - контракт описывает хранение, а модели описывают публичный API. Поле `experiences` переименовал в `experience`, чтобы запрос из ТЗ был валидным

### 4. Сидирование

Сидирование в файле `src/prisma/seed.ts` идемпотентное и транзакционное, перед вставкой проверяется существование профиля

## Допущения

- релизная версия призмы. Для полноценного продакшена пока что рано использовать 8 версию. Но это неплохая возможность для изучения 8 призмы на примере подобного тестового
- захардкоженные значения в `src/prisma/seed.ts`. Тестовое не предусматривает никаких мутаций, только чтение. Поэтому есть смысл указать все значения хардкодом, так как они не будут меняться
- отсутствет отдельный docker-compose.dev.yaml файл для дев мода. Так как проект небольшой, то можно вручную комментировать сервис сервера в docker-compose.yaml
